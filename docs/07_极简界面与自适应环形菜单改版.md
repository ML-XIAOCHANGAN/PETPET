# PETPET 极简界面与自适应环形菜单改版

> 更新日期：2026-08-09  
> 文档性质：本轮界面问题分析、设计决策与实现记录

## 一、用户反馈拆解

本轮反馈包含五项明确调整：

1. `MyPet` 页收起状态的陪伴栏横向占用过大，需要上下拉长、左右收窄。
2. 社区文字过多、层级混乱，需要增加猫咪图片、颜文字与可播放动画。
3. 首页悬浮窗按钮必须紧靠 `MyPet` 标题右侧；昼夜按钮固定在右上角；悬浮窗按钮位于昼夜按钮左侧。
4. 系统悬浮窗展开后应显示围绕小猫的环形菜单，并随悬浮位置自动改变展开方向。
5. 全局视觉需要从体素堆叠感收敛到极简风格。

## 二、现状问题分析

### 2.1 首页

- 原收起陪伴卡尺寸为 `72dp` 宽，内部仍显示标题、好感度与“展开”文案，横向视觉重量偏高。
- 顶部操作区把昼夜按钮放在悬浮窗按钮左侧，且两个按钮都远离标题，不符合指定顺序。
- 原体素按钮包含顶面、正面和侧面三层颜色，页面同时出现多个按钮时视觉噪声较大。

### 2.2 社区

- 页面由说明文字、发布表单、长正文、完整评论列表及多枚文字按钮连续堆叠，缺少图片形成的视觉锚点。
- 发布区域默认完全展开，占据首屏较大高度。
- 动态没有图片和运动反馈，社区气氛偏工具化。

### 2.3 系统悬浮菜单

- 原菜单只有水平单排，依据左右半屏切换顺序，不属于围绕悬浮窗的环形结构。
- 悬浮窗只能吸附左右边缘，无法覆盖位于顶部或底部时的自然展开方向。
- 菜单出现时没有从悬浮小猫中心向外展开的运动关系。

## 三、设计决策

### 3.1 极简视觉

- 保留现有业务调用接口，把按钮视觉改为单层圆角色块、细描边和轻微按压缩放。
- 底部导航改为一个低阴影圆角容器，仅对当前入口使用实色强调。
- 页面继续沿用现有日夜配色，不额外加入高饱和装饰色。

### 3.2 首页布局

- 顶部顺序调整为：`MyPet`、紧邻的爪印悬浮窗按钮、弹性留白、右上角昼夜按钮。
- 收起陪伴栏改为约 `48dp × 132dp` 的竖向胶囊，只保留“陪伴”、爱心、数值与展开箭头。
- 展开后再显示聊天次数、互动次数和领养日期，避免收起状态的信息拥挤。

### 3.3 社区内容

- 首屏增加“片刻放映”，自动轮播现有猫咪表情图，并提供播放／暂停控制。
- 每条动态增加一块大幅猫咪图片区域，点击播放后按帧切换表情，同时加入轻微呼吸和上下浮动。
- 动态正文限制为两行，评论区默认只显示最新一条；发布器默认收起为单行入口。
- 使用短颜文字作为情绪标签，减少解释性文案。
- 所有图片均复用项目已有 `drawable-nodpi` 猫咪资源，没有生成或覆盖原始资料。

### 3.4 自适应环形菜单

悬浮小猫展开时使用 `230dp × 230dp` 的透明区域承载半环菜单。系统按小猫到四条屏幕边缘的最短距离决定菜单朝向：

| 小猫最接近的边 | 菜单方向 |
| --- | --- |
| 左边 | 向右展开 |
| 右边 | 向左展开 |
| 上边 | 向下展开 |
| 下边 | 向上展开 |

三个菜单按钮以扇形分布在小猫周围，从小猫中心依次滑出并淡入。拖动结束后，小猫会吸附到距离最近的四边之一；下次展开时重新计算方向。展开区域调整窗口坐标时会抵消小猫在容器中的偏移，因此小猫本身不会因为菜单出现而跳位。

## 五、验收重点

1. 收起陪伴栏应明显变窄，并保持可点击区域与信息可读性。
2. `MyPet` 标题、悬浮窗按钮和昼夜按钮位置符合用户指定顺序。
3. 社区首屏不再出现大段说明，图片成为主要视觉内容。
4. “片刻放映”和动态图片均可播放、暂停。
5. 小猫分别吸附左、右、上、下边缘时，菜单都向屏幕内部展开。
6. 展开菜单时小猫位置不跳动，拖动时菜单自动收起。
7. 日间、夜间模式均保持足够对比度。
