# PETPET 0.2.0 架构与实现说明

> 更新日期：2026-08-09  
> 当前状态：源码可编译，静态检查通过  
> 开发语言：Kotlin  
> 界面框架：Jetpack Compose 与 Material3

## 一、功能实现

| 需求 | 当前实现 |
| --- | --- |
| 固定底部导航 | 顺序固定为 `My Pet`、成长、社区，默认进入 `My Pet` |
| 首页单屏布局 | 首页不再纵向滚动；聊天输入框固定在底部导航上方 |
| 主小猫 | 直接显示用户提供的主小猫图片，不使用程序画布绘制 |
| 持续动画 | 对原图片执行轻微呼吸缩放和上下浮动 |
| 点击互动 | 对原图片执行缩放、摇摆，并随机淡入用户提供的眨眼、害羞等表情图片 |
| 启动问候 | 每次创建应用状态时，从预置问候文案中随机选择一条 |
| 日夜模式 | `MY_PET` 页面提供开关，Material3 主题颜色平滑过渡 |
| 主题持久化 | DataStore Preferences 保存日夜模式偏好 |
| 我的模块 | 展示主人、宠物、相处天数、好感度和领养日期 |
| 小猫日记 | 支持新增、浏览并按时间倒序展示；空状态使用用户提供的爪印图片 |
| 日记持久化 | DataStore Preferences 保存日记数据 |
| 社区预留 | 保留动态、发布、喜欢、评论与举报的可扩展界面结构 |
| 页面动画 | 页面切换使用横向滑动与淡入淡出组合动画 |
| 悬浮小猫 | 使用用户提供的主小猫图片，可拖动、贴边、点击返回应用 |
| 悬浮窗自启动 | 用户主动开启后，应用启动或手机重启时尝试恢复悬浮服务 |
| 应用图标 | 桌面图标与圆形图标均引用用户提供的第一张应用图片 |

## 二、图片接入原则

本轮按用户最新要求执行以下规则：

1. 小猫外观、表情、爪印、悬浮头像和应用图标全部来自用户提供的图片。
2. 不再使用 Compose `Canvas`、安卓 `Canvas` 或路径命令绘制猫咪。
3. 程序只负责图片选择、切换、缩放、位移、旋转和淡入淡出。
4. 原始图片保存在 `docs/references/cat-assets`，不覆盖、不修改。
5. 安卓运行时使用的透明背景派生图保存在 `app/src/main/res/drawable-nodpi`。
6. 派生处理仅包括裁掉标记区域、移除与边缘相连的浅色背景、透明化和统一画布尺寸；封闭区域内的白色眼睛、鼻子、爪垫等细节保持不变。
7. 体素按钮仍按此前确定的体素按钮视觉规范构建；它不参与猫咪形象绘制。

## 六、动画说明

### 6.1 小猫图片动画

- 呼吸缩放：`0.985` 到 `1.025`，1900 毫秒往返；
- 浮动位移：上下各 4dp，2400 毫秒往返；
- 点击动效：680 毫秒内完成放大与左右摇摆；
- 表情切换：从主猫图片随机切换至一张互动表情，180 毫秒交叉淡入淡出，互动结束后恢复主猫图片。

### 6.2 页面与主题动画

Tab 页面使用横向滑动和淡入淡出组合动画。日夜主题的主要背景、表面、文字、容器和强调色在 500 毫秒内平滑插值。

## 七、悬浮窗规则

1. 用户首次主动点击开启悬浮小猫；
2. 用户授予显示在其他应用上层和必要的通知权限；
3. 应用记录用户允许自启动；
4. 下次打开应用且权限仍有效时自动恢复悬浮服务；
5. 手机重启后由启动广播接收器尝试恢复；
6. 用户点击“关闭并停用自启动”后清除自启动状态。

部分厂商系统可能拦截启动广播，正式发布时应按目标手机品牌提供系统自启动白名单指引，不能绕过用户设置。
