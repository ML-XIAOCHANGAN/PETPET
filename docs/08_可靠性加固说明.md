# PETPET 可靠性加固说明

## 一、范围

本轮仅处理安卓源码、构建配置、单元测试和本说明文档，不修改界面视觉资产、参考原图或既有截图。重点覆盖悬浮服务状态、权限回调、异常启动、业务时间与标识、持久化损坏以及测试可执行性。

## 二、审阅发现

| 问题 | 原有表现 | 风险 |
|---|---|---|
| 悬浮服务状态失真 | 按钮发出启动请求后立即写入“运行中”，服务挂载视图失败后仍可能再次写入“运行中” | 用户看到已开启，实际没有悬浮小猫 |
| 通知授权语义不清 | 安卓 13 及以上把通知授权与前台服务启动混为一个结果 | 拒绝通知后错误阻止悬浮宠物，或误以为前台服务不能运行 |
| 启动异常未保护 | 前台服务调度、通知前台化和悬浮视图挂载异常可沿主线程抛出 | 应用、开机广播或服务可能崩溃 |
| 时间和标识写死 | 仓库直接调用系统当前时间，并用毫秒时间戳充当标识 | 难以做确定性测试；同毫秒写入或时钟回拨可能产生重复标识 |
| 损坏数据静默变空 | 日记或社区的 JSON 解析失败后直接返回空列表，下一次写入会覆盖原文 | 用户数据在没有提示和备份的情况下丢失 |
| 中文路径下单测无法运行 | 构建进程强制统一编码，测试运行器生成的类路径参数与 Windows 系统解码不一致 | 测试类已经编译，但运行时报告找不到测试类 |

## 三、实现决策

### 3.1 悬浮服务状态

- “是否运行”改为进程内只读状态流，由服务维护；不再把瞬时运行态写入持久化配置。
- 只有前台通知启动成功且悬浮视图挂载成功后，服务才发布“运行中”。
- 用户首次开启时，也只有服务真正运行成功后才保存自动恢复意图；调度或挂载失败不会制造新的反复启动状态。
- 服务销毁、停止操作或权限失效时发布“未运行”。进程被系统终止后状态流天然回到“未运行”，不会读取到上次进程遗留的假状态。
- “用户是否允许自动恢复”仍单独持久化，避免把运行事实与用户意图混为一谈。

### 3.2 权限与异常

- 安卓 13 及以上先请求通知权限；无论用户允许还是拒绝，只要悬浮权限仍有效，就继续执行其主动开启悬浮宠物的意图。拒绝后的前台服务通知只会出现在任务管理器，不会出现在通知抽屉。
- 应用启动和开机恢复只把悬浮权限作为启动前提；通知权限用于改善常驻通知的可见性，不作为前台服务运行条件。
- 前台服务调度、通知渠道创建、前台化和视图挂载均增加失败保护与错误日志；失败时停止当前服务，不写入成功状态。
- 用户撤销悬浮权限并回到应用后，应用请求停止已有悬浮服务，但保留用户先前的自动恢复意图。

### 3.3 时间与标识

- 新增统一运行时值提供器，可注入固定时钟与自定义标识源。
- 数据仓库、日记、社区和聊天使用同一标识源。
- 默认标识源在同一进程内严格递增，即使同一毫秒连续创建数据或系统时钟短暂回拨，也不会重复。

### 3.4 持久化损坏

- 日记和社区的 JSON 编解码集中到独立组件，并返回“正常”或“携带损坏原文”的明确结果，不再用正常空列表伪装解析失败。
- 社区内容损坏时立即写入 `community_posts_corrupted_backup`，记录错误并向界面返回提示。
- 日记内容损坏时保持原字段不变并向界面提示；用户下一次保存日记时，在同一次 DataStore 事务内先写入 `diary_entries_corrupted_backup`，再保存新日记。
- DataStore 文件发生输入输出错误或结构损坏时只提供带警告的内存降级值，不配置自动替换处理器，因此原始文件不会被静默覆盖；后续写入失败会在界面提示。

### 3.5 测试运行器

- 移除构建进程的全局 `file.encoding` 强制项，避免额外干扰 Windows 测试工作进程；但原始中文项目路径下的类路径解码问题仍存在，不能据此宣称已经根治。
- 本轮使用指向同一工作区的纯英文目录联接运行测试。该做法不复制也不覆盖源码，并提供可重复的本机验证路径；后续持续集成应直接使用纯英文短路径检出项目。
- 增加 JSON 的仅测试运行时实现，使本地单元测试执行的编解码行为与安卓运行时一致。

## 四、自动化验证

本轮新增或扩充的测试覆盖：

- 每日奖励计数遇到负数损坏值时的修正；
- 固定时钟下日期、时间和标识的可预测性；
- 同毫秒与时钟回拨时标识严格递增；
- 日记及社区数据的中文、换行、评论和喜欢状态往返编解码；
- 损坏日记、负数喜欢数量不会被当成正常空数据。

执行命令（从纯英文目录联接运行）：

```powershell
F:\Agent-Program\PETPET_WORK\.tooling\gradle-8.9\bin\gradle.bat testDebugUnitTest --no-daemon
F:\Agent-Program\PETPET_WORK\.tooling\gradle-8.9\bin\gradle.bat lintDebug --no-daemon
F:\Agent-Program\PETPET_WORK\.tooling\gradle-8.9\bin\gradle.bat assembleDebug --no-daemon
```

2026 年 8 月 9 日的实际结果：纯英文目录联接下 12 项单元测试全部通过；静态检查为 0 个错误、20 个警告；调试包构建成功，产物为 `app/build/outputs/apk/debug/app-debug.apk`。原始中文目录直接运行单元测试仍会出现 `ClassNotFoundException`。现存警告来自可升级依赖、按要求保留但尚未使用的猫图、圆形启动图轮廓以及只由代码创建的自定义悬浮视图构造器，本轮未为消除警告而删除原始资产或扩大依赖升级范围。

## 五、仍需真机验证

- 安卓 13、14、15 上分别验证通知权限允许、拒绝、撤销后的按钮与服务状态。
- 至少两种厂商系统验证开机广播、后台启动限制和前台服务通知呈现。
- 使用调试注入或测试包破坏日记、社区数据，确认提示与备份字段符合预期。
- 系统强制结束进程、应用更新和设备重启后，确认悬浮视图没有残留且自动恢复符合用户意图。
