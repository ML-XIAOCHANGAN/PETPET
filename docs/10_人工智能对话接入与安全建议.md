# PETPET 人工智能对话接入与安全建议

## 一、当前事实

当前聊天由客户端关键词规则本地生成，没有接入开放人工智能接口，也没有模型密钥、服务端网关、内容审核或模型评测。现有规则式回复适合作为离线降级，不应对外描述为已经接入智能模型。

## 二、推荐架构

```text
安卓客户端 → PETPET 受控后端 → 内容审核与额度控制 → 开放人工智能响应接口
                                      ↓
                               安全降级与审计日志
```

- 安卓客户端只发送必要的会话内容和稳定匿名用户标识，不保存长期模型密钥。
- 模型密钥只存在于受控后端，通过环境变量或秘密管理服务注入；不得写入源码、安装包或公开仓库。
- 新文本生成优先使用响应接口，由后端统一执行超时、重试、限流、预算、审计和降级。
- 提示词随服务端代码版本管理，接受代码审查和自动化测试；生产环境固定模型快照，升级前先运行评测。

## 三、安全门槛

- 输入与输出都执行内容审核，并为自伤、未成年人、暴力、性内容、仇恨、诈骗和医疗建议设置明确处置策略。
- 限制单条输入、会话上下文和输出长度；丢弃与回复无关的长期历史，降低隐私暴露和提示注入风险。
- 对提示注入、越权索取系统提示词、诱导泄露他人信息、反复绕过审核等场景做对抗测试。
- 使用稳定的匿名安全标识关联滥用行为，不把手机号、邮箱或设备硬件标识直接传给模型供应商。
- 给用户提供举报、删除会话和高风险求助入口；明确模型可能出错，不能替代医疗、法律或紧急服务。
- 模型或审核服务不可用时，回退到当前本地规则式回复，并明确这是降级状态。

## 四、最小上线验收

1. 客户端安装包与源码中扫描不到模型密钥。
2. 服务端同时具备身份校验、单用户额度、全局限流、请求超时、幂等和成本监控。
3. 输入审核、输出审核和高风险固定响应均有自动化用例。
4. 提示词版本、模型快照和评测结果可追溯；升级失败可快速回滚。
5. 用户可举报、删除和注销；日志不记录不必要的聊天正文。
6. 对模型局限、数据用途、保留期限和人工复核范围给出用户可理解的说明。
